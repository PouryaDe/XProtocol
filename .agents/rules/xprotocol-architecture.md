# XProtocol Engineering & Platform Rules

1. **Project Identity & Parity**: Project name is **XProtocol**, built as a clean-room reverse-engineered copy of the Ovira panel architecture, features, protocols, and UI/UX animations/theme system. Brand icon uses the geometric interlocking X SVG (`BrandMark` + `web/public/xprotocol-logo.svg`).
2. **Target OS & Runtime Safety**: Real runtime drivers (`server/src/drivers/linuxEngine.ts`, `server/src/drivers/pki.ts`, `deploy/*.sh`) target **Ubuntu 22.04+ Linux** (`wg`/`awg`, `openvpn`, `ocserv`, `strongswan`, `xl2tpd`, `tc`, `ufw`, `certbot`, `systemd`, `xray`). Avoid `bash -lc` shell interpolation; always invoke binaries with `execFile` argument arrays and sanitize CRLF/quoted strings in generated daemon configs. Windows is used only as a dev editor host (with PowerShell `;` command chaining).
3. **Database**: Uses Node 24 built-in `node:sqlite` (`DatabaseSync`) with WAL mode in `server/src/db/database.ts` (`xprotocol.db`). Keep schema migrations idempotent inside `initDatabase()`.
4. **Peer Eligibility & Accounting**: Never include disabled, expired, used-up, or unauthorized clients in server configs—always resolve through `server/src/services/peerResolver.ts`. Live peer sync (`syncService.ts`) and 5s telemetry/quota/device-limit/reset enforcement (`collector.ts`) must gracefully degrade when running non-Linux tests.
5. **Security & Auth**: Cookie-based HMAC sessions (`xprotocol_session`, `HttpOnly`, `SameSite=Lax`), `X-CSRF-Token` enforcement on state-changing routes, scrypt password hashing, TOTP 2FA with recovery codes, scoped API tokens, and strict owner/reseller RBAC isolation.
6. **UI/UX**: Bilingual English (LTR) + Persian (RTL), `system`/`dark`/`light` themes (`mint` obsidian-emerald dark & warm stone light), 8 accent presets, slide-over drawers, cursor-tracking `.xp-card` spotlight effects, and staggered entrance animations.
7. **Verification**: Never mark work complete without running `npm run typecheck`, `npm run build`, and `npm test` after the final edit.
